# Логика реконструкции и сшивки треков

## 1. Формирование хитов

Из данных события создаются объекты `hit`. Каждый хит содержит координату `z`, измеренные координаты `x` и/или `y`, погрешности измеренных координат и тип плоскости (`ZX`, `ZY`, `ZXY`). Именно векторы `hit` принимает алгоритм трекинга.

## 2. Разделение детектора на две области

Внешний код разделяет хиты события на два набора по принадлежности к области до магнита и после магнита:

- `hitsBefore` — хиты до магнита;
- `hitsAfter` — хиты после магнита.

## 3. Реконструкция прямых в каждой области

Для каждого набора хитов выполняется логика поиска, реализованная в tracking:

1. Хиты группируются по измерительным плоскостям отдельно для проекций `ZX` и `ZY`.
2. В выбранном алгоритме (CKF или Hough) находятся кандидаты в каждой проекции.
3. Кандидаты `ZX` и `ZY` объединяются по общему хиту типа `ZXY`.
4. По объединённым хитам создаётся объект `track`, который аппроксимирует один прямолинейный участок:

   - `x(z) = a*z + b`;
   - `y(z) = c*z + d`.

## 4. Сшивка двух наборов прямых

После реконструкции областей код имеет два набора:

- `vector<track> tracksBefore`;
- `vector<track> tracksAfter`.

Функция `stitchTracks(tracksBefore, tracksAfter)` должна сопоставить прямые, принадлежащие одной частице, определить импульс (по искревлению траектории в магнитном поле) и создать для каждой успешно сшитой пары объект:

`real_track(tracksBefore[i], tracksAfter[j], momentum)`.

## 5. Состав `real_track`

`real_track` содержит ровно два прямолинейных объекта:

- `trackBefore` — участок до магнита;
- `trackAfter` — участок после магнита.

Импульс передаётся в конструктор `real_track` и также записывается в оба вложенных `track` через `setMom()`.

## 6. Идентификация частицы и скорость

После сшивки PID-блок по данным калориметров передаёт массу:

1. `real_track.setMass(mass)`;
2. `real_track.calculateBeta()`.

`beta = p / sqrt(p*p + mass*mass)`.

Рассчитанное значение `beta` также записывается в оба вложенных `track` через `setBeta()`. Для идентификации частиц (для связи трека с ливнем в калориметре) необходимо использовать реконструированный трек.

## 7. Вычисление неопределённостей

После получения импульса и массы у обоих прямолинейных участков доступны кинематические параметры (импульс и скорость), необходимые последующему расчёту `Q` и ковариаций. Для определения погрешностей для каждого из `track`, образующих `real_track`, требуется пройтись ещё раз по обоим треком методом `calculateCovariances`. После этого следует использовать полученные неопределённости для определения точности идентификации частиц (связь трек - ливень) и трекинга (связь трек - ячейка годоскопа).

# 8. Результат

В конце обработки из вектора `hit` получаются вектора `real_track`, включающие массы и импульсы частиц, образующих трек, и 2 прямолинейных трека `track`, для каждого из которых могут быть вычислены координаты и неопределённости координат в точке `z`.
